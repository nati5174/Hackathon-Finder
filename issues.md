  1. Email alerts (highest impact)                                                                                                                                                                                                                                                                                      
  Users sign up with their email + preferences (e.g. location, in-person only). When the daily scrape finds a new hackathon with travel reimbursement, they 
  get an email. This is what turns a one-time visitor into a returning user. Without this, people check once and forget about the site.

  
  2. Better filtering

  Right now only name/location search exists. Add:
  - Region filter (North America, Europe, etc.)
  - Format filter (in-person vs hybrid)
  - Date range (e.g. only show hackathons in the next 3 months)

  ---
  3. More data sources

  MLH is ~30-50 hackathons per season. Adding Devpost and Devfolio would multiply that significantly and make the app much more useful. The scraper
  architecture already supports this cleanly.

  ---
  4. User accounts + bookmarks (nice to have at scale)

  Let users save hackathons they're interested in. Needed to support email alerts properly too.

  ---
  Priority order I'd suggest:

  Email alerts → filtering → more sources → accounts

  Email alerts alone would drive most of the retention you need to grow to 1000 users. Want to start with that?
